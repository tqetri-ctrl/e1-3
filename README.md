# Mini NPU Simulator

AI 가속기(NPU)의 핵심 연산인 **MAC(Multiply-Accumulate)** 을 흉내 내어, 3×3 ~ 25×25 크기의
패턴이 십자가(Cross)인지 X인지 판별하는 Python 콘솔 애플리케이션입니다.
외부 라이브러리 없이 표준 라이브러리(`json`, `time`, `re` 등)만 사용합니다. (Python 3.8+)

## 실행 방법

```bash
python main.py
```

실행하면 모드를 고릅니다.

| 선택 | 모드 | 설명 |
| :-- | :-- | :-- |
| `1` | 사용자 입력 (3×3) | 필터 A, 필터 B, 패턴을 한 줄씩(공백 구분) 입력 → 점수/시간/판정 → 3×3 성능 표 |
| `2` | data.json 분석 | 같은 폴더의 `data.json`을 읽어 일괄 판정 → PASS/FAIL → 성능 표(3·5·13·25) → 결과 요약 |

| `3` | 보너스 | 크기 N을 입력하면 N×N 십자가/X 패턴을 생성·판정하고, 2D vs 1D MAC 성능 비교 표 출력 |

- 모드 1에서 행/열 개수가 맞지 않거나 숫자가 아니면 안내 문구를 출력하고 해당 줄부터 다시 입력받습니다.
- `data.json`은 `main.py`와 같은 폴더에 두어야 하며, 실행 위치(현재 디렉터리)에 `data.json`이 있어야 합니다.
- 테스트: `python -m unittest`

### 파일 구성

| 파일 | 역할 |
| :-- | :-- |
| `main.py` | 실행 엔트리포인트, 모드 1/2 흐름, 결과 요약 출력 |
| `npu_simulator.py` | MAC 연산, 라벨 정규화, epsilon 판정, 행렬 검증 |
| `data_loader.py` | 콘솔 입력 파싱/검증, `data.json` 로드와 케이스 단위 검증 |
| `benchmark.py` | 크기별 MAC 시간 측정과 표 출력 |
| `bonus.py` | (보너스) 패턴 생성기, 1D 평탄화 MAC, 2D/1D 비교 |
| `data.json` | 필터(5/13/25)와 샘플 패턴 7개 |
| `test_phase*.py` | 단위 테스트 |

### data.json 형식

```json
{
  "filters":  { "size_5": { "cross": [[...]], "x": [[...]] }, "size_13": {...}, "size_25": {...} },
  "patterns": { "size_5_1": { "input": [[...]], "expected": "+" }, ... }
}
```

패턴 키 `size_{N}_{idx}`에서 N을 뽑아 `size_N` 필터와 연결합니다.

## 구현 요약

- **MAC 연산**: 이중 `for` 루프로 `Σ pattern[i][j] × filter[i][j]`를 직접 누적합니다 (`npu_simulator.mac`). 크기가 다르면 `ValueError`.
- **라벨 정규화**: 내부 표준 라벨은 `Cross`, `X` 두 가지입니다. expected 값과 필터 키 모두
  `+`, `cross`, `Cross`, `CROSS` → `Cross` / `x`, `X` → `X`로 바꾼 뒤 비교·출력합니다 (대소문자·앞뒤 공백 무시).
  알 수 없는 라벨은 해당 케이스(또는 해당 크기 필터)를 FAIL로 처리합니다.
- **동점 정책(epsilon)**: `abs(score_a - score_b) < 1e-9`이면 동점으로 보고 `UNDECIDED`(모드 1은 "판정 불가")를 냅니다.
  `UNDECIDED`는 어떤 expected와도 일치하지 않으므로 모드 2에서는 FAIL로 집계됩니다.
- **오류 격리**: 모드 2는 케이스마다 예외를 잡아 `FAIL + 사유`로 기록하고 다음 케이스를 계속 처리합니다.
  파일 없음·JSON 깨짐·최상위 구조 오류는 에러 메시지만 출력하고 종료 없이 돌아옵니다.
- **성능 측정**: `time.perf_counter()`로 `mac()` 호출 구간만 10회 반복해 평균(ms)을 구합니다. 입출력은 포함하지 않습니다.

## 결과 리포트

### 1. 실패 케이스 분석

현재 `data.json`(7개 케이스) 실행 결과는 **총 7개 / 통과 7개 / 실패 0개**입니다.
실패가 0이 된 이유는 세 가지 방어 정책이 각각 다른 종류의 실패를 미리 흡수했기 때문입니다.

1. **라벨/스키마 문제 → 정규화로 흡수**: expected가 `+`, `x`, `cross`, `Cross`로 제각각이고 필터 키도 `cross`/`x` 소문자입니다.
   표준 라벨(Cross/X)로 통일하지 않았다면 판정 `Cross`와 expected `+`가 문자열로 달라 **로직은 맞는데 FAIL**이 났을 것입니다.
2. **수치 비교 문제 → epsilon으로 흡수**: `size_13_3`은 잡음(0.1)이 섞인 패턴이라 X 점수가 `3.4000000000000012`처럼 부동소수점 꼬리가 붙습니다.
   점수를 `==`로 비교하면 같은 값도 다르게 보이거나 우연히 순서가 뒤집힐 수 있어, `1e-9` 허용오차 안이면 동점으로 처리합니다.
   (예: `0.1 + 0.2`와 `0.3`은 정확히는 다르지만 epsilon 안이라 동점이 됩니다.)
3. **데이터 문제 → 케이스 단위 FAIL로 격리**: 크기 불일치, `expected` 누락, 알 수 없는 라벨, 숫자가 아닌 값, 필터 누락은
   프로그램을 중단시키지 않고 해당 케이스만 FAIL로 기록하며 사유가 요약에 출력됩니다. (단위 테스트로 7종을 확인했습니다.)

실패가 생긴다면 원인은 다음처럼 분리해 진단합니다. 요약의 사유 문구가 **크기 불일치/누락/알 수 없는 라벨**이면 데이터·스키마 문제,
**판정 X != expected Y**이면 로직 또는 expected 값 문제, **동점(UNDECIDED)**이면 점수 차이가 1e-9 미만인 수치 비교 문제입니다.

### 2. 성능 표 해석과 시간 복잡도 O(N²)

MAC은 N×N 칸을 한 번씩 곱하고 더하므로 **연산 횟수는 정확히 N²** 이고, 시간은 이에 비례하는 **O(N²)** 입니다.
아래는 이 개발 환경(Python 3.14, Windows)에서 같은 크기를 2000회 반복해 얻은 평균 시간의 한 예입니다.

| 크기 | 연산 횟수(N²) | 평균 시간(ms) | 연산 1회당 시간(µs) |
| :-- | --: | --: | --: |
| 3×3 | 9 | 0.0025 | 0.28 |
| 5×5 | 25 | 0.0045 | 0.18 |
| 13×13 | 169 | 0.029 | 0.17 |
| 25×25 | 625 | 0.090 | 0.14 |

- 13×13 → 25×25는 연산 횟수가 약 3.7배(625/169)인데 시간은 약 3.1배(0.090/0.029)로, N²에 가깝게 증가합니다.
  5×5 → 13×13도 연산 횟수 6.8배, 시간 6.4배로 비슷합니다. 즉 연산 1회당 시간이 거의 일정(0.14~0.18µs)하다는 뜻이며, 이것이 O(N²)의 근거입니다.
- 3×3에서 연산 1회당 시간이 더 큰 것은 **함수 호출·루프 설정 같은 고정 오버헤드**가 연산 9번에 나뉘어 상대적으로 크게 보이기 때문입니다.
  크기가 커질수록 이 고정 비용이 희석되어 N² 비례에 가까워집니다.
- 기본 측정(10회 평균)은 마이크로초 단위의 짧은 구간이라 실행마다 값이 꽤 흔들립니다. 실제로 3×3과 5×5의 순서가 바뀌어 보이는 경우도 있으며,
  이는 타이머 해상도와 OS 스케줄링 잡음 때문이지 N² 관계가 깨진 것은 아닙니다. 반복 횟수를 늘리면 위 표처럼 추세가 안정됩니다.
- 시사점: 필터가 수백×수백으로 커지면 N²배로 연산량이 폭증하므로, 곱셈을 병렬로 동시에 처리하는 NPU가 필요해집니다.
  이 시뮬레이터는 모든 MAC을 순차 실행하므로 시간이 연산 횟수에 그대로 비례합니다.

## 보너스 결과

### 패턴 생성기

`bonus.generate_cross(n)` / `generate_x(n)`이 N×N 십자가(가운데 행·열)와 X(두 대각선) 패턴을 만듭니다.
모드 3의 판정과 2D/1D 비교의 입력으로 재사용되며, N=3일 때 미션의 예시 패턴과 동일합니다.
(N이 짝수이면 십자가의 중심선은 `N//2`번째 행/열입니다.)

### 2D vs 1D MAC 비교

`mac_1d`는 2차원 리스트를 길이 N²의 1차원 리스트로 평탄화한 뒤 단일 `for` 루프로 누적합니다.
동일한 입력(Cross 패턴 × X 필터), 동일한 반복 횟수로 측정하며, 평탄화 변환 자체는 측정 구간 밖에서 한 번만 수행합니다.
두 방식의 점수가 같은지도 매번 확인합니다. 이 환경에서 2000회 반복한 결과 예시:

| 크기 | 2D(ms) | 1D(ms) | 2D/1D |
| :-- | --: | --: | --: |
| 3×3 | 0.0023 | 0.0013 | 약 1.7x |
| 5×5 | 0.0058 | 0.0030 | 약 1.9x |
| 13×13 | 0.029~0.034 | 0.024 | 약 1.2~1.4x |
| 25×25 | 0.093~0.122 | 0.067~0.081 | 약 1.4~1.5x |

1D가 대체로 1.2~2배 빠릅니다. 이중 루프의 안쪽 루프 설정과 `pattern[i][j]`의 두 번 인덱싱이 사라져
인덱싱·루프 오버헤드가 줄기 때문입니다. 다만 연산 횟수(N²)는 같으므로 시간 복잡도는 두 방식 모두 O(N²)이고,
이득은 상수 배수에 그칩니다. 측정값은 실행마다 흔들리므로 위 수치는 경향으로만 봐야 합니다.
