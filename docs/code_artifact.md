# Mini NPU Simulator 구현 계획 (Implementation Plan)

본 문서는 `mission.md`에 명시된 요구사항, 제약 사항, 보너스 과제 및 제출물 명세를 누락 없이 충족시키기 위한 단계별 개발 및 검증 계획을 정의합니다.

---

## 1. 개요 및 설계 목표

* **언어 및 제약 조건**: Python 3.8 이상, 외부 라이브러리(NumPy, Pandas 등) 사용 금지, 표준 라이브러리(`json`, `time`, `typing` 등)만 사용.
* **핵심 연산**: N×N 2차원 또는 1차원 데이터 구조에 대한 수동 반복문 기반 MAC (Multiply-Accumulate) 연산 구현.
* **유연성 및 안정성**:
  * 부동소수점 오차 방지를 위한 Epsilon 기반 점수 비교 ($\varepsilon = 10^{-9}$).
  * 라벨 정규화(Standardization): `'+'`, `'cross'`, `'Cross'` $\rightarrow$ `Cross` / `'x'`, `'X'` $\rightarrow$ `X`.
  * 예외 처리: 데이터 크기/행렬 규격 불일치, 입출력 파싱 오류 발생 시 비정상 종료 없이 안전하게 복구 또는 케이스 단위 `FAIL` 처리.

---

## 2. 모듈 구조 설계

단일 실행 구조(`main.py`) 또는 모듈화 구성을 고려하되, 전체 코드가 명확하고 관리가 용이하도록 내부 구조를 세분화합니다.

```
project/
├── main.py                # 실행 엔트리포인트 (CLI 흐름 및 모드 제어)
├── npu_simulator.py       # 핵심 로직 (MAC 연산, 라벨 정규화, Epsilon 비교, 데이터 구조)
├── data_loader.py         # 콘솔 입력 검증 및 data.json 로드/검증/정규화
├── benchmark.py           # 성능 측정 (크기별 반복 측정, O(N²) 분석용 데이터 수집)
├── bonus.py               # (보너스) 1D 최적화 연산 및 N×N 패턴 자동 생성기
├── data.json              # 테스트 데이터셋
└── README.md              # 실행 방법 및 결과 리포트 (실패 원인 분석, 복잡도 서술)
```

*(참고: 파일 제출 제약이나 단일 파일 구성이 필요할 경우 `main.py` 내 클래스/함수로 응집력 있게 구조화 가능)*

## 3. 단계별 구현 절차

### Phase 1: 기반 데이터 구조 및 핵심 알고리즘 구현

1. **데이터 구조 정의 및 변환 모듈**
   * N×N 행렬(2차원 리스트) 구조 지원.
   * 입력 형태 및 행렬 검증(행 개수 = N, 모든 열 개수 = N 여부 체크) 함수 개발.
2. **MAC (Multiply-Accumulate) 연산 구현**
   * 외부 라이브러리 없이 이중 `for` 루프를 사용한 순수 MAC 연산 작성.
   * $$\text{Score} = \sum_{i=0}^{N-1} \sum_{j=0}^{N-1} (\text{Pattern}[i][j] \times \text{Filter}[i][j])$$
3. **라벨 정규화 (Label Normalization) 함수**
   * 대소문자 및 기호 변환 맵핑 구현:
     * `'+'`, `'cross'`, `'CROSS'`, `'Cross'` $\rightarrow$ `'Cross'`
     * `'x'`, `'X'` $\rightarrow$ `'X'`
4. **부동소수점 오차 반영 및 동점 비교 판정기**
   * 두 점수 $S_A, S_B$에 대해 $|S_A - S_B| < 10^{-9}$ 일 경우 `'UNDECIDED'` (판정 불가) 반환.
   * $S_A > S_B$ 면 `'A'`(또는 `'Cross'`), $S_B > S_A$ 면 `'B'`(또는 `'X'`).

---

### Phase 2: 사용자 입력 모드 (Mode 1 - 3×3) 구현

1. **콘솔 입력 파서 및 예외 처리**
   * 3줄 입력 처리: 각 줄당 공백으로 구분된 3개의 숫자 파싱.
   * 파싱 실패(문자 포함), 행 수(3줄 미만/초과) 및 열 수(3개 미만/초과) 불일치 시 직관적인 에러 메시지 출력 후 재입력 루프 진입.
2. **필터 A, B 및 패턴 입력 flow 구축**
   * 사용자로부터 필터 A, 필터 B, 패턴 순으로 입력받아 메모리에 저장.
3. **결과 출력 및 3×3 벤치마킹**
   * MAC 연산 수행 및 10회 반복 연산 시간 측정(ms 단위).
   * 필터 A 점수, 필터 B 점수, 평균 연산 시간, 판정 결과 출력.

---

### Phase 3: JSON 데이터 처리 및 스키마 검증 모드 (Mode 2 - data.json) 구현

1. **`data.json` 로더 개발**
   * JSON 구조 로드: `filters` (`size_5`, `size_13`, `size_25`) 및 `patterns` (`size_{N}_{idx}`) 파싱.
2. **키 파싱 및 필터 매칭 알고리즘**
   * 패턴 키(예: `size_5_1`)에서 크기 $N$을 추출하여 대응되는 `size_N` 필터 셋과 자동 매칭.
3. **스키마 및 규격 검증 (Fault Tolerance)**
   * 필터 규격과 패턴 규격(N×N)의 일치 여부 검증.
   * 규격 불일치 또는 데이터 누락 시 프로그램을 중단하지 않고, 해당 케이스를 `FAIL`로 기록하고 사유 명시.
4. **일괄 판정 및 PASS/FAIL 검증**
   * Cross 필터 점수 및 X 필터 점수 계산.
   * 최종 판정(Cross / X / UNDECIDED)과 `expected` 라벨(정규화 적용) 비교.
   * 일치 시 `PASS`, 불일치 시 `FAIL` 처리.

---

### Phase 4: 성능 분석 (Benchmark) 및 표 출력 모드

1. **I/O 제외純수 연산 시간 측정**
   * 연산 구간 전후로 `time.perf_counter()`를 사용하여 시간 측정.
   * 크기별(3×3, 5×5, 13×13, 25×25) 10회 반복 측정 후 평균 연산 시간(ms) 산출.
2. **성능 분석 표(Table) 콘솔 출력**
   * 항목: 크기($N \times N$), 평균 시간(ms), 연산 횟수($N^2$).
   * 정렬된 형식으로 보기 쉽게 구성.

---

### Phase 5: 결과 요약 및 리포트 출력 기능 구현

1. **콘솔 요약 리포트**
   * 총 테스트 케이스 수, PASS 수, FAIL 수 요약 출력.
   * FAIL 케이스 발생 시 케이스 ID 및 원인(예: 규격 불일치, 동점 규칙 적용 등) 목록화.
2. **`README.md` 작성**
   * 실행 가이드 (모드 선택 방법, 실행 명령어).
   * 구현 요약 (라벨 정규화, MAC 알고리즘, Epsilon 오차 비교 정책).
   * **결과 리포트 섹션 (최소 10줄 이상)**:
     * FAIL 원인 상세 분석 (0 FAIL인 경우 정규화 및 epsilon 정책이 오차를 흡수한 이유 설명).
     * 크기 $N$ 증가에 따른 $N^2$ 연산 횟수와 실제 측정 시간 간의 시간 복잡도 $O(N^2)$ 상관관계 논리적 서술.

---

### Phase 6: 보너스 과제 구현 (선택 사항)

1. **시뮬레이터 최적화 (1D 메모리 접근)**
   * 2차원 리스트를 1차원 평탄화(Flattened) 리스트로 변환하여 1D 루프 MAC 구현.
   * 동일 입력 및 동일 반복 횟수로 2D vs 1D MAC 연산 속도 최적화 전/후 비교 표 출력.
2. **N×N 패턴 자동 생성기**
   * 크기 $N$ 입력 시 $N \times N$ 크기의 십자가(Cross) 및 X 패턴 자동 생성 알고리즘 구현.
   * 생성된 패턴을 성능 측정 및 테스트 데이터로 활용할 수 있도록 모듈화.
